## 7. Server actions (проверка кода)

Отдельно не вызывались извне, потому что работают через сессию пользователя, и всё, что они делают, ограничено RLS и внешними ключами из раздела 1. Дополнительно в коде:
- все id проходят `z.uuid()`; чужие id дают «не найдено» (RLS);
- пути фото принимаются только вида `{свой user_id}/{этот item_id}/{uuid}.jpg` (`isOwnPhotoPath`), остальные отклоняются, загруженные файлы при ошибке удаляются;
- удаление аккаунта заново проверяет пароль.

## Предупреждения Supabase (advisors)

| Предупреждение | Оценка |
|---|---|
| `keepalive` (SECURITY DEFINER) доступна anon | Намеренно: у cron нет сессии. Функция только обновляет время в `system_status`. |
| `delete_my_account` (SECURITY DEFINER) доступна вошедшим | Намеренно: удаляет только `auth.uid()`. |
| `keepalive` доступна вошедшим | Безвредно. |
| Выключена защита от утёкших паролей | Настройка Auth (Authentication → Sign In / Providers → Email). Рекомендуется включить, если доступна на вашем тарифе. |

## Принятые риски

1. **Отметку keepalive можно подделать.** Любой, у кого есть публичный anon key (он есть в коде страницы), может вызвать `keepalive()` и обновить время «Последняя проверка базы». Данные при этом не раскрываются и не меняются. Принято сознательно (этап 7).
2. **CSP ограниченная.** Включены `frame-ancestors`, `base-uri`, `object-src`; полный CSP со `script-src` не включён: Next.js вставляет inline-скрипты, а строгая политика с nonce потребовала бы отключить статическую отдачу страниц. React экранирует вывод, `dangerouslySetInnerHTML` в коде не используется.
3. **Отметку онбординга пользователь может изменить** (`user_metadata`): это повлияет только на повторный показ подсказок.
4. **Карта исходников service worker** (`/serwist/sw.js.map`) доступна публично: в ней только код worker'а, секретов нет.
